**Type:** exhaustive, adversarially-verified, **report-only** (no code/deps/migrations changed — validate-not-build freeze respected).
**Method:** 6 finder surfaces × 2 discovery rounds → 40 candidates → one independent skeptic per candidate tasked to *refute* it → 29 verdicts (**15 CONFIRMED, 11 PLAUSIBLE, 3 REFUTED**) → deduped to **10 canonical findings**. Load-bearing facts re-verified by hand.
**Supersedes/expands** the old "**P7** = turn on RLS for ~17 service-role tables" backlog line (Sessions 12/14/15). RLS alone does **not** close these — the root cause is *no auth layer + service-role for every user action*.

## Correction the adversarial pass produced (important)

An earlier premise (and my own scout seed) claimed *"`NEXT_PUBLIC_*` ⇒ anon key is in the browser bundle ⇒ every RLS-off table is directly readable/writable over the internet."* **Verified false:** `NEXT_PUBLIC_SUPABASE_ANON_KEY`/`_URL` are referenced **only** in `src/lib/supabase/server.ts` (server-only — imports `next/headers`) and one test. There is **no `createBrowserClient`, no client-side Supabase usage**, and the real keys are not committed (`.env.example` empty, `.env*` gitignored). A `NEXT_PUBLIC_` var is inlined into the browser bundle *only where client-bundled code references it* — none does. **So the "anon key → direct PostgREST → RLS-off table" vector is NOT reachable today.** The RLS-off tables remain a real *latent* misconfiguration (F6), but the live exploit path is **unauthenticated Next.js Server Actions** (below), which need no anon key.

## Detail — top findings

### F1 · No auth + service-role everywhere (High, CONFIRMED)
`supabaseApp` is aliased to `supabaseService()` (`server.ts:30`), which uses `SUPABASE_SERVICE_ROLE_KEY` and bypasses RLS. The only middleware (`src/proxy.ts`, this fork's rename) returns `NextResponse.next()` unconditionally; `(app)/layout.tsx` has no session check. Every `"use server"` function imported by a client component becomes a public POST RPC running as service-role, and each trusts a caller-supplied `profileId` rather than deriving identity from a session. **Umbrella cause of F2–F5 and F7.**
**Fix (already in-repo):** `src/server/targeting-actions.ts:7` is the correct pattern — it calls `supabaseServer()` (anon + RLS) to verify `profiles` ownership and throws *"Profile not found or access denied"* before touching the service-role client. Apply that guard to the vulnerable actions, and/or add a real `middleware.ts`/session gate over the `(app)` group. Stop aliasing `supabaseApp = supabaseService` for request-time user writes.

### F2 · Unauthenticated sniper actions (High, CONFIRMED) — most urgent
`createManualSniperAlert`, `actOnSniperAlert`, `confirmSentReply`, `recordReplyOutcome` (`sniper-actions.ts`) are public Server Actions (imported by `manual-sniper-form.tsx`, `sniper-pins.tsx`, `reply-outcome-list.tsx`). The owner's `profileId` is serialized into the public `/engage` payload; live `alertId`s come back from `getSniperPins`. Chain: `createManualSniperAlert(profileId,…)` returns a new `alertId` → `actOnSniperAlert(…, "acted")` → `recordReplyOutcome(…, {reply_impressions, author_reply_back})`, writing fully fabricated "acted + outcome" rows into `sniper_alerts` (RLS off, service-role). **This silently corrupts the GATE-2 go/no-go scorecard** — the sole deliverable of the current freeze (`gate.ts:66-80`, `scorecard.ts:61-129` trust these rows with no cross-check). Separately, each `createManualAlert` fires `embedText` (paid OpenAI embeddings, `sniper.ts:439,444`) *before* dedup → **unbounded unauthenticated OpenAI cost**. (Drafting LLM cost is env-dependent: default `GEN_BACKEND=subscription` spawns a local `claude` CLI absent on Vercel; only `GEN_BACKEND=gemini` incurs draft spend.) URL is safe (`parseTweetUrl` regex-only, never fetched — no SSRF); text renders escaped (no stored XSS).
**Fix:** F1's ownership guard on all four actions; rate-limit `createManualSniperAlert`.

### F3 · OAuth callback credential-bind takeover (Medium, CONFIRMED)
`callback/route.ts` verifies only the CSRF `state` cookie — proves `/start` and `/callback` ran in the *same browser*, not that it's the owner's. `getActiveProfile()` returns the single global profile; token upsert uses `onConflict: "profile_id"`. An attacker runs the whole flow in their own browser, consents with **their** Google account, and their `refresh_token` overwrites the owner's — future `uploadVideo` (`youtube.ts:54`) pushes to the attacker's channel. Requires `YOUTUBE_CLIENT_ID/SECRET` configured in prod. *(Clean: `origin→redirectUri` cannot exfiltrate the token — a `refresh_token` grant has no redirect.)*
**Fix:** require an authenticated owner session on `/start` and re-verify it in `/callback` before the upsert.

### F4 · Push hijack/eavesdrop (Medium, CONFIRMED)
`savePushSubscription(profileId, sub)` (`push-subscriptions.ts:11`) is a public Server Action, no auth, service-role, `onConflict:"endpoint"` (an *add*, so the owner keeps receiving — stealthy). Simplest variant needs no forged request: any visitor clicking "Enable sniper alerts" on the unauthenticated `/engage` enrolls their own device under the shared profile and thereafter receives the owner's push stream. `removePushSubscription(endpoint)` takes only an endpoint (no profile/auth) → notification-silencing DoS. Bounded: push body is public `tweet_text.slice(0,140)` + `/engage` (the private draft goes only to Telegram); crons paused.
**Fix:** resolve `profileId` from the session, not the argument; scope delete by `profile_id AND endpoint`.

### F5 · Publish arbitrary file read/delete (Medium, CONFIRMED, env-gated)
`publishProjectVideo(filePath)` (`publish.ts:21`) is a public Server Action; `filePath` is unvalidated and flows into `createReadStream` (`youtube.ts:69`, arbitrary read) and `unlink` (`publish.ts:55`, arbitrary delete). No ownership check. The `stage==='publish'` UUID gate is defeatable because `/studio` serializes `listVideoProjects` `select('*')` (incl. `id`, `stage`) into the public payload. Brakes holding it at Medium: uploads are forced `private` to the *owner's* channel (real exfil-to-attacker needs chaining F3); on Vercel `/var/task` is read-only (delete confined to `/tmp`; no on-disk `.env` — secrets are in `process.env`).
**Fix:** `realpath(filePath)` must start with `os.tmpdir()` + the `embalio-` prefix, else reject — ideally pass an opaque upload token, not a path. Add the ownership check.

### F6 · RLS off on 11 tables + default anon grants (Medium *latent*)
`signal_tweets`, `tweet_metric_snapshots`, `activity_events`, `topic_history`, `follower_snapshots`, `analytics_daily`, `predictions`, `strategy_snapshots`, `watch_targets`, `sniper_alerts`, `push_subscriptions` all `disable row level security` and **no migration issues any `GRANT`/`REVOKE`**, so Supabase's default `anon`/`authenticated` grants remain and `config.toml` exposes the `public` schema. RLS is the only gate and it's off. Exploitable over PostgREST **only if the anon key becomes obtainable** — not true today (see correction above). It's one `createBrowserClient`/leaked-key away from full internet read/write, and the Supabase Data-API exposure changes (May 30 / Oct 30 2026) make pre-emptive hardening worthwhile.
**Fix:** `enable row level security` on each (no policy needed — the app's service-role client bypasses RLS, so functionality is unaffected; anon then default-denies), plus `revoke all … from anon, authenticated`.

### F7 / F8 / F9 / F10 (lower)
- **F7** — `projects.ts` / `profiles.ts` (`addSeedTarget`/`listSeedTargets`/`createProfile`) / `watch-targets.ts` (`addWatchTarget`/`removeWatchTarget`) are the same unauth-service-role pattern; low marginal impact in single-tenant, but real authz gaps + `writeScriptForProject` LLM-cost amplification. `toggleProfileOptimized` already guards `FIXED_PROFILE_ID` — extend that guard to the siblings.
- **F8** — `studio/upload` POST writes an uploaded file to `tmpdir()` with no auth; bounded by Vercel's ~4.5 MB body cap + ephemeral `/tmp` (path traversal already blocked by the filename sanitizer). Gate on auth; add a size/type check.
- **F9** — `buildTopicBoardPrompt` (`voice-prompt.ts:240`) and `buildVoiceSystem` skip the `frameUntrusted()`/`UNTRUSTED_DATA_NOTICE` that peer prompts apply. Bounded: topic-board runs local-worker-only (never called from the app), scoring is deterministic, posting is human-gated, and `claude` WebFetch has its own SSRF guards. Add the framing for consistency.
- **F10** — `youtube_credentials.refresh_token` is plaintext at rest; only reachable after a service-role/DB compromise (the table *does* have RLS on, so it's not anon-reachable). Encrypt at rest if/when Studio unfreezes.

## Surfaces checked and found clean

- **Cron auth (all 6 crons + nudge/pulse/telegram-poll):** `cronAuthError` is the first statement in every one, before any DB/Apify/LLM side effect. Constant-time (`timingSafeEqual` + non-secret length short-circuit), **fails closed** when `CRON_SECRET` unset (500), compares the full `Bearer <secret>` string (no prefix/substring bypass). All export **GET only** — no method-confusion. Error-detail-in-JSON sits behind that auth.
- **CSRF:** `youtube/oauth/start` mints a 32-byte HttpOnly, path-scoped, 10-min state cookie (secure conditioned on https); callback compares constant-time and clears it one-time. (Gap is missing *owner* auth = F3, not the CSRF check.)
- **SSRF:** none. Manual-sniper URL is regex-parsed for id/handle and **never fetched**; only outbound fetches are hardcoded `api.github.com`, OpenAI/Google SDKs, and the local `claude` CLI — none take tweet/media-derived URLs. Apify page fetches run in Apify's cloud. No image-generation sink.
- **Prompt safety (reply/thread/original/reply-filter/reply-draft):** external text wrapped in `frameUntrusted()` + `UNTRUSTED_DATA_NOTICE`; `sanitizeForPrompt` strips tags (kills `</untrusted_data>` breakout) + control chars. Score is deterministic (`targetScore`) — LLM has no influence on it. Draft is **never auto-posted** — only an `encodeURIComponent`'d `x.com/intent` prefill behind `REPLY_INTENT_ENABLED`, human tap required. `spawn('claude', …, {shell:true})` passes the prompt via **stdin, not argv** — no shell injection.
- **Secrets:** no server-only secret (`SERVICE_ROLE`, `CRON_SECRET`, `YOUTUBE_CLIENT_SECRET`, `TELEGRAM_*`, `APIFY_TOKEN`, `VAPID_PRIVATE_KEY`, `GOOGLE/OPENAI/ANTHROPIC`) appears in any of ~60 `"use client"` files. `next.config.ts` has no `env`/`publicRuntimeConfig`. No token/refresh-token/Authorization-header logged. No secrets in git (key-pattern scan across history = 0 hits). Next masks Server Action error messages in prod.
- **RLS that IS correct:** `profiles`, `seed_targets`, `candidates`, `drafts`, `posts` (`0002_rls`), `posting_accounts`/`posting_jobs` (`0003`), `recording_profiles` (`0009`), `video_projects` (`0010`), `youtube_credentials`+`algorithm_briefs` (RLS on, no policy = default-deny), `research_briefings` (re-enabled `20260530`). `posting.ts`/`posts.ts` use `supabaseServer()` (anon+RLS) and **fail closed** with no session. `refreshTargets` (`targeting-actions.ts:7`) is the reference ownership pattern.
- **Path traversal (`studio/upload`):** filename sanitized `/[^a-zA-Z0-9._-]/g` + mandatory `embalio-<ts>-` prefix → cannot escape `tmpdir`.
